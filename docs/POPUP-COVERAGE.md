# 승인·질문 전체 지원 기준

점검일: 2026-09-21. 클라이언트·호스트 Codex 26.915.4065.0. 기존 요청 분기와 각 follower 응답 버전이 유지되는 것을 양쪽 설치 파일에서 다시 확인했다.

현재 설치 코드에서 양쪽 모두 아래 9개 요청 분기를 확인했다. 요청 문구는 모델과 도구에 따라 달라지므로 문장을 인식하지 않고 요청 유형·ID·선택 범위·응답 규약으로 연결한다. 이 목록의 존재는 해당 기능의 구현 완료를 의미하지 않는다.

## 현재 지원과 남은 연결

| 요청 분기 | 사용자가 보는 내용 | 0.19.0 구현 | 남은 검증/제한 |
|---|---|---|---|
| `item/commandExecution/requestApproval` | 터미널 실행, 실행 정책, 네트워크 정책 | 명령·STDIN·제시된 정책 선택 전달 | 새 하위 유형 실제 화면 왕복 |
| `item/fileChange/requestApproval` | 파일 변경 허용·거부 | 4개 선택 전달, 변경 내역 해시 대조 | 실제 화면 왕복 |
| `item/permissions/requestApproval` | 인터넷·파일 시스템 추가 권한 | 요청된 권한 그룹과 이번 턴/세션 선택 지원 | 사용자 화면 왕복 확인, 더 넓은 권한·다른 환경 거부 유지 |
| `item/tool/requestUserInput` | 선택지·직접 입력·여러 질문 | 질문 ID별 답변·부분/빈 응답 전달 | 실제 화면 왕복 |
| `mcpServer/elicitation/request` | 앱·사이트 사용, 폼, 로그인·플러그인 확인 | 일반 폼·URL·앱/사이트 확인 전달 | 인증/설치/파일 선택은 GPU 필요 |
| `item/plan/requestImplementation` | 계획대로 실행 | 원본 계획 실행과 Plan → Default 전환 | 편집한 계획·닫기 미지원, 실제 화면 왕복 필요 |
| `item/tool/requestOptionPicker` | 옵션 선택·닫기 | 직접 응답으로 연결이 끊기는 문제 방지·안내 | 공식 앱에 follower 응답 경로 없음 |
| `item/tool/requestSetupCodexContextPicker` | 초기 설정·환경 선택 | 남아 있는 요청 안내 | 현재 GPU 공식 앱에서 자동 dismiss; 원격 사용자 선택 경로 없음 |
| `item/tool/call` | 일부 도구의 설정·입력 화면 | `request_onboarding_input` 답변 전달 | 옵션 선택·setup step은 GPU 필요 |

MCP 응답은 원래 GPU의 `thread-follower-submit-mcp-server-elicitation-response` 처리 함수를 통과한다. 실행 내용에 묶인 승인은 기억된 권한으로 확대할 수 없다. 일반 폼은 필드 이름·필수 값·유형·열거 선택·배열·숫자 범위 등을 검증한다. 확장 폼의 스칼라/선택 필드도 같은 경로를 사용한다. 파일 선택, 이미지 선택, 정규식/$ref 및 알 수 없는 스키마는 GPU 처리가 필요하다.

브라우저 인증, 커넥터 계정 연결, 플러그인 설치 제안은 응답 하나 외에도 GPU의 인증·설치 완료 확인이 필요해 원격 완료로 표시하지 않는다. 거부/취소 응답은 검증된 MCP 응답 경로로 전달할 수 있다. 일반 URL의 ‘계속’은 공식 앱이 보내는 빈 객체를 보존하며, URL을 열었다는 이유만으로 전송하지 않는다.

로그인은 승인 응답 하나로 완료되지 않을 수 있다. 사용자 직접 인증과 GPU 계정으로 연결되는 완료 신호를 검증한다. Windows 관리자 확인, GPU 앱의 저장·덮어쓰기 창, 사용량 한도나 서버 오류는 위 승인 응답과 별도 흐름이다.

## 공통 전달 계층의 요구사항

각 어댑터가 공통 등록 목록에 원래 요청, 응답 메서드·버전, 입력 검증기, 완료 관찰 조건을 등록한다. 명령·권한·폼 내용을 임의로 같은 허용 응답으로 바꾸지 않는다.

- 수신 즉시 요청의 지원 여부를 판별한다. 미지원 유형과 GPU 공식 앱에서 처리할 방법을 연결 창 본문에 표시한다. 안내는 GPU 기록과 원래 요청을 바꾸지 않는다.
- 사용자가 실제 선택한 값만 원래 GPU 작업의 활성 요청에 전달한다. 기본 선택이나 대기 시간은 승인으로 취급하지 않는다.
- 허용 기간, 네트워크 대상, 파일 권한, 질문 ID, 입력 스키마를 보존한다. 요청 내용이 달라지면 전달하지 않는다.
- 승인·질문 응답을 일반 메시지로 대체하지 않는다. 비밀번호·인증 값·일반 폼 본문은 진단에 저장하지 않는다.
- 응답 전송과 GPU 처리 확인을 구분한다. 다른 기기에서 먼저 처리한 요청, 전송 후 단절, 중복 클릭, 재시작 후 불확실한 결과는 재전송하지 않는다.
- 알 수 없는 새 요청은 무조건 전달하지 않는다. 지원 불가 이유가 보이는 상태로 두고 규약 검증과 회귀 검사를 추가한다.

## 모든 유형의 완료 기준

| 검사 | 통과 조건 |
|---|---|
| 표시 | GPU와 노트북에서 같은 요청과 선택 범위 확인 |
| 허용·거부·취소 | 모든 제공된 선택이 원래 의미대로 한 번만 전달 |
| 입력 | 선택형·자유 입력·여러 질문·빈 응답을 스키마와 질문 ID로 검증 |
| 상태 변경 | 다른 기기의 응답, 요청 만료, 소유자/턴 변경을 감지 |
| 연결 장애 | 전송 전 실패와 전송 후 결과 불확실을 구분하고 중복 실행 방지 |
| 재시작 | 기록된 응답이 자동 재전송되지 않음 |
| 실행 위치 | 권한·파일·앱·계정 변화가 원래 GPU 작업에 적용됨 |
| 실제 화면 | 격리된 전송 검사와 사용자의 실제 버튼 왕복 확인을 각각 기록 |

위 기준 전체를 충족하기 전에는 “모든 팝업 지원”이라고 표시하지 않는다. 0.19.0은 공통 전달·중복 방지·미지원 안내 및 위 지원 항목을 구현했다. 실제 GPU 업무 승인을 만들어 자동 허용하는 대신 격리된 IPC/WebSocket 검사를 사용했다. 미지원 경로와 아직 실행하지 않은 실제 화면 검증은 위 표에 남겨 둔다.
