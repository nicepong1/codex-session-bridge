# 문제 해결

## 이미지가 있는 작업에서 timeout 또는 연결 끊김이 반복됨

0.19.6은 변경 때마다 큰 대화 전체를 전송했습니다. 0.19.7은 초기 상태를 압축하고 이후 변경분만 전송하며, 실제 수신 중인 데이터를 무응답으로 오판하지 않습니다. 양쪽 PC에 같은 버전을 설치하고 연결 창을 다시 여세요. 실제 네트워크 단절이나 GPU 응답 실패까지 없어지는 것은 아닙니다. 결과가 불확실한 메시지는 GPU의 실제 대화에 들어갔는지 먼저 확인하고, 바로 반복 전송하지 마세요.

## 전송된 텍스트가 작성란에 남아 있음

Codex 26.915.4065.0의 원격 입력 경로는 성공 응답 뒤에도 작성란 정리에 사용하는 콜백을 호출하지 않는 경우가 있습니다. 0.19.7은 이 공식 화면 동작을 고치지 않습니다. 위 대화에 동일한 메시지와 답변이 나타났다면 이미 전송된 것이므로 작성란의 남은 문장을 직접 지워 주세요. 전송 여부가 불확실하면 먼저 GPU 대화를 확인하세요.

## 이미지 첨부가 텍스트 제한 오류로 거절됨

0.19.7부터 텍스트 16,000자 이하와 PNG/JPEG/GIF/WebP 이미지 최대 4개·합계 8MB를 지원합니다. 일반 파일·원격 이미지 URL·이미지만 단독 입력은 아직 지원하지 않습니다. 이미지 내용은 입력 경로에서 전달하며 진단 기록에는 내용 대신 개수·크기·해시만 남깁니다.

## 인터넷 복구 후 휴대폰에는 최신 대화가 보이지만 노트북은 멈춰 있음

0.19.0 이하에서는 통신만 복구되고 선택한 대화가 다시 열리지 않아 `no-client-found`가 반복될 수 있습니다. 대화를 다시 열 때 내부 상태 번호가 재시작되면 이전 번호와 비교하여 계속 차단하는 경우도 있습니다. 0.19.1은 같은 대화·소유자를 확인하고 현재 연결에서 전체 상태를 새로 받아 복구합니다. 전송 여부가 불확실한 지시·승인은 자동으로 재전송하지 않습니다.

양쪽 PC에 같은 최신 릴리스를 설치하세요. 설치 후에도 기존 연결 창은 이전 버전일 수 있습니다. 미전송 입력문을 보관하고 **연결용 앱을 트레이에서도 종료**한 뒤 아이콘으로 다시 여세요. GPU에서 실행 중인 원래 Codex 작업을 종료할 필요는 없습니다. 소유자 자체가 바뀌었다면 새 연결 창에서 다시 확인해야 합니다.

0.19.3부터 GPU 연결이 끊기면 남아 있는 본문을 최신 상태로 표시하지 않고, **마지막으로 받은 내용이며 이후 GPU 작업이 반영되지 않았을 수 있음**을 본문에 안내합니다. 앱·CLI 업데이트로 연결이 시작되지 않은 경우에도 일반 SSH 오류 대신 호환성 원인을 구분합니다. 새 GPU 전체 상태를 실제로 받은 뒤에만 안내가 사라지고 입력이 다시 활성화됩니다.


## 바탕 화면에서 client.json 또는 설치 정보를 찾을 수 없음

Codex 같은 MSIX 앱 안의 터미널에서 설치하면, Windows가 AppData 쓰기를 앱 전용 LocalCache로 옮길 수 있습니다. 같은 사용자·같은 경로 문자열이어도 바탕 화면 Explorer에서는 파일이 보이지 않습니다. 0.18.3은 이런 실행 환경에서 설치를 완료 처리하지 않습니다.

1. 릴리스 ZIP을 압축 해제하고 **Windows 파일 탐색기에서 Install.cmd를 실행**하세요. 앱 내부 터미널에서 재설치를 반복하지 마세요.
2. 노트북은 Client, 작업 PC는 Host 역할을 선택하세요.
3. 연결 설정이 없다면 Configure.cmd로 다시 등록하세요. 예전 설정이 필요하면 앱 전용 `LocalCache/Local/CodexSessionBridge`를 먼저 백업하세요. 인증키나 Codex 계정 데이터를 옮길 필요는 없습니다.
4. 앱 안에서 여는 시험과 별도로, 바탕 화면 아이콘을 직접 눌러 검증하세요.

Windows 동작: [Microsoft MSIX 문서](https://learn.microsoft.com/en-us/windows/msix/desktop/flexible-virtualization).


먼저 설치 폴더의 `Diagnose.cmd`를 실행합니다. 설정을 바꾸려면 `Configure.cmd`, 호스트 정보는 호스트의 `Show-HostInfo.cmd`를 사용합니다.

| 증상 | 확인할 내용 |
|---|---|
| `SSH key authentication failed` | SSH 사용자명, 개인 키, 호스트 공개 키 등록 위치와 ACL. 암호문 키는 ssh-agent 등록 여부 |
| `SSH host key changed or is missing` | 호스트의 실제 지문 확인. 변경이 정상이라면 새 연결로 다시 등록. 기존 검사를 무시하지 않음 |
| `Host unavailable` | Tailscale 연결, 호스트 전원·SSH 서비스·포트·방화벽, 호스트 설치 여부 |
| `Install the same bridge release` | 양쪽 ZIP 버전을 동일하게 설치 |
| `client.compatible: false` | 노트북 Codex 앱 버전과 설치 형태 확인 |
| `host.appCompatible: false` | 호스트 Codex 앱 실행 여부, SSH와 같은 Windows 사용자, 지원 버전 확인 |
| `cliCompatible: false` | 호스트 공식 앱을 열어 CLI 캐시가 준비됐는지 확인. 지원 버전 확인 |
| `ipcReady: false` | 호스트 공식 앱을 로그인한 채로 열어 두었는지 확인 |
| 다른 호스트로 전환되지 않음 | 기존 연결용 앱을 종료한 뒤 Configure.cmd에서 선택하고 다시 실행 |
| 본문은 보이지만 입력이 안 됨 | 사전 읽기 화면일 수 있음. 실제 호스트 작업 연결까지 대기 |
| 프로젝트 폴더를 찾지 못함 | 노트북 로컬 경로와 호스트 경로 구분, 공유 서버 이름과 연결 주소 일치 여부 |
| 승인 버튼이 반응하지 않음 | [지원표](APPROVALS.md) 확인 후 미지원 요청은 호스트 공식 앱에서 처리 |
| 연결은 됐는데 실행기 초기화 오류 | 호스트 샌드박스·도구 설치·폴더 권한 문제를 별도로 확인 |

기본 연결이 아직 없으면 바탕 화면 아이콘이 최초 설정을 엽니다. 연결 시작이 실패하면 안내 창을 표시합니다. 임시 네트워크 문제는 재연결을 시도할 수 있지만 입력·승인 결과가 불확실하면 자동 재전송하지 않습니다.

개발자에게 이슈를 보낼 때는 OS, 양쪽 앱 버전, 브리지 버전, 오류 종류, 재현 순서만 먼저 공유하세요. `reports`, 임시 공식 앱 프로필, SSH 키, 계정 파일 또는 업무 대화를 통째로 올리지 마세요.

## 설치 중단 후 복구 (0.18.1 이상)

복사 중 오류가 발생하면 원인을 처리한 뒤 같은 설치기를 다시 실행합니다. 파일은 `.staging-*` 폴더에서 모두 검증한 후 설치되므로, 미완성 폴더가 다음 실행을 막지 않습니다. 실패한 임시 폴더는 진단용으로 보존되며 설치 위치로 선택되지 않습니다.

이전 설치기가 남긴 미완성 버전 폴더는 완료 명세와 설치 포인터가 없고, 남은 파일이 배포본과 일치하며, 해당 폴더를 사용하는 프로세스가 없을 때만 `.incomplete-*` 폴더로 보존한 뒤 복구합니다. 변경된 파일·알 수 없는 파일·연결된 폴더가 있거나 프로세스 조회에 실패하면 자동 복구하지 않습니다. `Existing installation differs`가 계속되면 해당 폴더를 삭제해 우회하지 말고 오류 종류를 확인하세요.

보존된 `.staging-*`와 `.incomplete-*`는 `%LOCALAPPDATA%\Programs\CodexSessionBridge\versions` 안에 있습니다. 설치와 실행이 정상임을 확인하고 진단에 필요하지 않을 때 사용자가 정리할 수 있습니다. 현재 설치 포인터가 가리키는 일반 버전 폴더나 사용자 데이터 폴더와 구분하세요.

### 파일 일부가 잘려 자동 복구가 거부된 경우

복사 중 중단된 파일과 변조된 파일은 해시만으로 구분할 수 없어 자동으로 이동하지 않습니다. 오류의 파일명과 대상 경로를 확인하세요. 관련 프로그램과 설치기를 닫고, `client.json` 및 `host.json`의 `installPath`가 해당 경로를 가리키지 않는지 확인합니다. 완료 명세가 없거나 명세 자체가 잘렸다면, 신뢰할 수 있는 ZIP과 내용을 대조한 뒤 **해당 폴더 전체를 다른 이름으로 바꾸어 보존**하고 설치기를 다시 실행할 수 있습니다. 파일을 삭제하거나 기존 설치를 덮어쓰는 방법으로 복구하지 않습니다. 정상적인 완료 명세가 있거나 설치 포인터가 가리키는 폴더라면 이 수동 복구 대상이 아닙니다.

OneDrive의 파일 표식은 허용하지만 실제 심볼릭 링크·정션·알 수 없는 재분석 지점은 거부합니다. 온라인 전용 파일은 다운로드가 끝나야 해시 검증과 복사가 가능합니다.

같은 Windows 계정을 콘솔·RDP 등 여러 로그인 세션에서 사용하는 경우에도 연결 창은 하나만 지원합니다. 다른 로그인 세션에서 창을 이어서 표시하는 동작은 검증하지 않았습니다. 먼저 기존 세션의 연결 창을 종료한 뒤 새 로그인 세션에서 실행하세요.

실행 중 진단 폴더가 삭제되거나 디스크가 가득 차면 연결을 중단하지 않고 해당 실행의 진단 저장을 멈춥니다. `launch-error.txt`에 `Diagnostic report disabled`가 남을 수 있으며, 그 뒤의 보고서는 최신 상태가 아닙니다. 디스크 문제를 해결한 뒤 연결 창을 정상 종료하고 다시 실행하면 진단 저장을 재개합니다.
