# 아이콘을 열 때 업데이트 점검

0.19.10부터 바탕 화면 아이콘으로 **새 연결 창을 열 때 한 번** 양쪽 앱·CLI·브리지와 GitHub 최신 정식 릴리스를 비교합니다. 이미 열린 창을 선택하거나 시작 중 아이콘을 다시 누르면 점검을 반복하지 않습니다. 주기적 예약 작업과 Windows 로그인 시 실행 작업은 등록하지 않습니다.

호환되는 새 브리지가 있으면 다음 순서로 자동 적용합니다.

1. 고정된 `nicepong1/codex-session-bridge` 공개 저장소의 정식 릴리스와 양쪽 역할의 호환성을 확인합니다.
2. GitHub가 제공한 ZIP SHA256, ZIP 내부 파일 명세, 호환성 파일을 검증하고 양쪽 PC에 파일을 준비합니다.
3. 공식 앱 버전이 바뀌지 않았는지 확인하고 호스트, 클라이언트 순서로 설치 포인터를 변경합니다. 기존 공식 앱과 작업을 종료하지 않습니다.
4. 새 설치 경로에서 연결 창을 엽니다. 프로필·SSH 호스트 키·기존 바로가기는 유지합니다.

업데이트가 없으면 조회만 하고 기존 버전으로 엽니다. GitHub 조회가 실패해도 현재 양쪽 조합이 지원되면 연결합니다. 조회 실패를 ‘최신 버전’으로 처리하지 않습니다. 조회는 요청별 시간 제한이 있으며, 실제 새 패키지를 받는 경우에는 다운로드·검증 때문에 더 오래 걸립니다.

두 PC의 설치 전환은 네트워크를 거치므로 동시에 완료되지는 않습니다. 전환 도중 응답이 끊기면 창을 열지 않고 재실행 안내를 표시합니다. 다시 아이콘을 누르면 같은 검증된 배포본으로 양쪽 상태를 확인하고 이어서 맞춥니다. 다른 설치가 포인터를 바꾼 경우 덮어쓰지 않으며, 이미 더 최신인 호스트를 구버전으로 내리지 않습니다. 설치 폴더를 직접 고정한 고급 프로필은 자동 적용하지 않고 수동 정렬을 안내합니다.

실행 결과는 `%LOCALAPPDATA%\CodexSessionBridge\updates\launch-status.json`에 기록합니다. `Check-Updates.cmd`는 별도의 **읽기 전용** 진단이며 설치하지 않습니다. 진단 결과는 같은 폴더의 `status.json`에 저장합니다.

| 상태 | 동작 |
|---|---|
| `ready` | 현재 조합으로 연결 |
| `compatible-update-available` | 양쪽을 지원하는 배포본을 검증 후 적용 |
| `bridge-version-mismatch` | 정렬할 검증된 배포본이 없으면 안내 후 중단 |
| `compatibility-validation-required` | 새 앱/CLI 조합 검증이 필요하므로 연결 중단 |
| `host-unavailable` | GPU 전원·로그인·Tailscale·SSH 확인 안내 |

공식 Codex 자동 업데이트와 브리지 릴리스는 별개입니다. 이 점검은 공식 Codex를 강제로 업데이트하거나 알 수 없는 버전의 차단을 해제하지 않습니다. 새 Codex를 지원하는 브리지 배포본이 아직 없다면 새 호환성 검증과 릴리스가 필요합니다. PC가 꺼져 있거나 아이콘을 열지 않는 동안에는 점검하지 않습니다.
