# 업데이트와 호환성 점검

공식 Codex의 자동 업데이트와 Session Bridge 릴리스는 별개입니다. 공식 앱이 먼저 바뀌면 브리지가 새 버전을 검증할 때까지 연결이 차단될 수 있습니다. 작업 데이터가 삭제된 것은 아닙니다. 알 수 없는 버전은 계속 차단하며, 버전 번호만 추가해 통과시키지 않습니다.

`Check-Updates.cmd`는 노트북 앱, GPU에서 실행 중인 앱·설치된 앱·CLI, 양쪽 브리지 및 GitHub의 최신 정식 릴리스를 비교합니다. 기존 SSH 연결의 호스트 키 검증을 그대로 사용합니다. 결과는 `%LOCALAPPDATA%\CodexSessionBridge\updates\status.json`에 저장합니다. 이 명령은 읽기 전용이며 앱을 종료하거나 설치하지 않습니다.

| 상태 | 다음 행동 |
|---|---|
| `ready` | 현재 조합으로 연결 가능 |
| `compatible-update-available` | 양쪽 PC를 지원하는 새 브리지 확인; 해당 릴리스 ZIP을 검증하고 양쪽에 설치 |
| `bridge-version-mismatch` | 양쪽 브리지 릴리스 맞추기 |
| `compatibility-validation-required` | 새로운 앱/CLI 조합의 통신 규약 및 실제 연결 검증 필요 |
| `host-unavailable` | GPU 전원·로그인·Tailscale·SSH 확인 |

GitHub 조회 실패는 '최신 버전'으로 처리하지 않습니다. 현재 조합이 검증되어 있으면 네트워크상의 업데이트 조회 실패만으로 연결을 막지 않습니다. 업데이트 조회는 정상 창 실행의 필수 단계가 아니므로 매번 GitHub 응답을 기다리게 하지 않습니다.

## 사전 점검 자동화

Codex의 예약 기능으로 이 점검을 주기적으로 실행하도록 설정할 수 있습니다. 자동화는 별도로 설정해야 하며 이 배포본을 설치한다고 자동으로 생기지는 않습니다. 기존 연결 설정이나 작업 내용은 공개 저장소에 올리지 마세요.

자동화는 새 버전이 감지되면 호환성 규약, 회귀 테스트, 설치 무결성 및 실제 읽기 연결을 검사한 뒤 브리지를 양쪽에 적용해야 합니다. GitHub의 태그와 ZIP 해시가 일치하는지 검증하고 기존 연결 설정을 유지합니다. 앱 창에 미전송 입력이 있거나 GPU 작업이 실행 중이면 앱 종료나 재시작은 보류합니다. 불확실한 메시지를 재전송하거나 승인 요청에 자동으로 답하지 않습니다.

공식 앱 업데이트를 먼저 강행하거나, 호환성 검증 없이 차단만 해제하는 것은 자동화에 포함하지 않습니다. 새 공식 앱의 패키지와 통신 규약을 확보하기 전에는 호환성을 미리 보장할 수 없습니다. PC가 꺼져 있거나 네트워크가 끊겨 있는 동안에도 실행된다고 가정하지 마세요.
