# 사용설명서

## 1. 준비

호스트는 실제 프로젝트와 실행 도구가 있는 Windows x64 PC입니다. 노트북은 원격으로 지시할 Windows x64 PC입니다. 두 PC가 서로 다른 Windows 사용자명·설치 경로를 사용해도 됩니다. 각 사용자는 본인 계정과 접근 권한을 준비해야 합니다.

- [호환성 표](COMPATIBILITY.md)의 공식 Codex 앱과 호스트 CLI 버전을 확인합니다.
- 두 PC에 공식 Codex를 설치하고 로그인합니다. 호스트에서는 공식 앱을 열어 둡니다.
- Tailscale을 사용할 경우 두 PC를 같은 tailnet 또는 허용된 공유 기기로 연결합니다. [Tailscale Windows 설치 안내](https://tailscale.com/kb/1022/install-windows)를 참고하세요.
- 호스트에 Windows OpenSSH Server, 노트북에 OpenSSH Client가 필요합니다. [Microsoft 설치 안내](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse)를 따르세요.
- 호스트는 절전·종료 상태가 아니어야 합니다. 화면 잠금이나 앱 로그인 세션 상태에 따라 일부 Computer Use 작업은 호스트 조작이 필요할 수 있습니다.

## 2. SSH 키 인증 준비

이미 비밀번호 입력 없이 키 인증으로 연결된다면 기존 키를 사용할 수 있습니다. 브리지는 SSH 비밀번호를 보관하지 않습니다.

처음이라면 노트북 PowerShell에서 키를 생성합니다. 파일 이름과 암호문을 직접 지정하고, 개인 키는 노트북 밖으로 옮기지 않습니다.

```powershell
ssh-keygen -t ed25519
```

암호문이 있는 키는 Windows `ssh-agent`에 등록합니다. 서비스 활성화는 관리자 권한이 필요할 수 있습니다. `ssh-add`는 일반 사용자 PowerShell에서 실행합니다.

```powershell
ssh-add "$env:USERPROFILE\.ssh\id_ed25519"
```

호스트에는 **공개 키 `.pub` 내용만** 등록합니다. 일반 사용자는 해당 사용자의 `.ssh\authorized_keys`, 관리자 그룹 사용자는 보통 `%ProgramData%\ssh\administrators_authorized_keys`를 사용합니다. 파일 ACL과 그룹별 위치가 다르므로 [Microsoft의 Windows 키 인증 안내](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)를 그대로 확인하세요.

브리지는 비밀번호 로그인으로 자동 전환하거나 키 검사를 생략하지 않습니다. 계정 키를 분실했거나 권한이 바뀌면 SSH부터 복구합니다.

## 3. 호스트 설치

1. GitHub Releases에서 `codex-session-bridge-0.18.3-windows-x64.zip`과 `.sha256` 파일을 받습니다. ZIP의 `Get-FileHash -Algorithm SHA256` 결과를 체크섬 파일과 비교합니다.
2. ZIP을 **압축 해제**합니다. 압축 파일 안에서 직접 실행하지 않습니다.
3. `Install.cmd`를 두 번 클릭하고 `2`를 입력합니다. 프로그램은 현재 Windows 사용자의 LocalAppData에 설치됩니다.
4. 설치 화면에 표시되는 Windows 사용자명, Tailscale 주소, `SHA256:...` 형식의 SSH 호스트 지문을 확인합니다. 다시 보려면 설치 폴더의 `Show-HostInfo.cmd`를 실행합니다.
5. 호스트의 Codex 앱은 로그인한 채로 열어 둡니다. SSH 사용자와 Codex를 실행한 Windows 사용자는 같아야 합니다.

설치가 끝나도 OpenSSH가 준비되지 않았다면 지문이 표시되지 않습니다. 1~2단계의 SSH 준비를 먼저 마칩니다. 설치 프로그램은 SSH 서버·방화벽·공유 폴더·업무 파일 권한을 자동 변경하지 않습니다.

## 4. 노트북 설치와 최초 연결

1. 같은 ZIP을 노트북에서 압축 해제하고 `Install.cmd` → `1`을 선택합니다.
2. 연결 이름, 호스트 주소, 호스트 Windows 사용자명, SSH 포트(기본 22)를 입력합니다.
3. 기존 SSH 개인 키의 전체 경로를 입력합니다. 기본 키 또는 `ssh-agent`를 사용하면 빈칸으로 진행할 수 있습니다. 키의 **내용**을 입력하지 않습니다.
4. 호스트를 기본 방식으로 설치했다면 고급 설치 경로도 빈칸으로 둡니다. 호스트 사용자별 설치 경로가 자동으로 해석됩니다.
5. **호스트 화면에서 확인한 SSH SHA256 지문**을 입력합니다. 노트북에서 수집한 서버 키와 다르면 저장하지 않습니다.
6. 연결 진단 결과에서 `ready: true`를 확인합니다. `false`이면 설정은 저장되지만 연결은 준비되지 않은 상태입니다. [문제 해결](TROUBLESHOOTING.md)을 처리한 뒤 `Diagnose.cmd`로 다시 확인합니다.

이후 바탕 화면의 **Codex Session Bridge** 아이콘을 사용합니다. 이미 연결 창이 있으면 해당 창을 다시 표시합니다. 별도의 일반 Codex 창과 혼동하지 않도록 연결 창을 따로 배치하면 편합니다.

## 5. 일상 사용

- 사이드바에서 호스트 작업을 선택하고 내용을 확인한 뒤 지시를 보냅니다.
- 프로젝트는 새 연결 창에서 기본적으로 접혀 있습니다. 필요한 프로젝트를 펼쳐 작업을 선택합니다.
- 모델/추론 수준 변경은 호스트의 실제 설정에 전달됩니다.
- 새 프로젝트 등록 시 선택하는 폴더는 **호스트의 경로**여야 합니다. 노트북에 연결한 네트워크 드라이브는 서버 이름이 연결 설정과 정확히 일치할 때 호스트가 보고한 공유 경로로 변환합니다. IP로 등록했다면 같은 IP로 매핑한 공유 드라이브를 사용하세요.
- 연결을 종료하려면 연결 창의 앱을 종료합니다. 호스트에서 이미 실행 중인 작업을 자동으로 중단하지 않습니다.
- 승인 종류별 지원 여부는 [승인·질문 지원표](APPROVALS.md)를 확인합니다.

## 6. 여러 호스트와 다른 사용자

설치 폴더의 `Configure.cmd`에서 새 연결 `N`을 선택해 호스트를 추가합니다. 기존 번호를 선택하면 기본 연결이 바뀝니다. 전환 전에 기존 연결용 앱을 종료합니다. 현재는 사용자당 원격 연결 창 하나를 지원합니다.

다른 사람은 자기 PC에서 자기 Windows 계정으로 설치하고 본인이 접근 가능한 호스트를 등록하면 됩니다. 설치 ZIP에는 개발자의 연결 정보나 대화가 들어 있지 않습니다. 기존 사용자의 LocalAppData 폴더를 복사해서 공유하지 않습니다.

## 7. Android

Android에는 이 Windows 프로그램을 설치하지 않습니다. 공식 ChatGPT 앱의 Remote에서 호스트를 연결합니다. 공식 앱에서 해당 기능이 제공되고 호스트 연결이 완료되어야 합니다. 이 프로젝트가 Android 연결 서버나 별도 모바일 앱을 제공하는 것은 아닙니다.

## 8. 업데이트와 제거

연결용 앱을 종료한 뒤 새 릴리스 ZIP을 양쪽에 설치합니다. 버전별 새 폴더를 만들고 기존 연결 설정은 유지합니다. 실행 중인 호스트 작업을 업데이트 때문에 종료하지 않습니다. 양쪽 브리지 버전이 다르면 연결이 차단됩니다.

이전 버전은 자동 삭제하지 않습니다. 문제가 생기면 이전 ZIP의 `Install.cmd`를 다시 실행하여 이전 설치를 선택할 수 있습니다. 복구하려는 버전이 현재 Codex 앱과 호환되는지도 확인해야 합니다.

제거하려면 **설치된 버전 폴더**의 `Uninstall.ps1`을 PowerShell로 실행합니다. 그 버전의 프로그램과 해당 바로가기·설치 포인터만 제거합니다. 연결 설정, SSH 키, 중복 방지 기록, Codex 계정 및 프로젝트는 보존합니다.

설치 프로그램은 압축 해제 후 **Windows 파일 탐색기에서 Install.cmd를 실행**하세요. Codex 같은 MSIX 앱 내부 터미널에서는 설치 파일이 앱 전용 폴더에 저장될 수 있어 0.18.3부터 설치를 거부합니다.
