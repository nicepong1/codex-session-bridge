# 릴리스 검증 기록

## 0.19.5 — 목록 갱신과 열기 지연

- 298개 작업 환경에서 기존 0.19.3 연결 창의 전체 목록 재검색이 약 4초씩 10초 간격으로 반복되고, 본문 사전 읽기 대기열이 최대 250개까지 증가한 상태를 확인. 선택한 작업의 실제 소유자 연결은 저장 본문 유무에 따라 수백 ms에서 약 10초까지 차이가 났음.
- 사전 읽기 후보를 최신 32개로 제한하고 목록 순위 교체·클릭 즉시 읽기·초기 5초 유예·30초 목록 간격을 자동 검사. 새 최상단 작업 발견 뒤 목록 캐시가 폐기되고 다음 첫 페이지가 새 작업으로 시작하는지 확인.
- 298개 전체 작업 순서를 창 시작 경로에서 제거하고, 프로젝트 목록과 마지막 선택 작업만 확인한 뒤 화면을 여는 구조로 자동 검사. 첫 최근 페이지가 전체 목록 스캔 없이 반환되고, 백그라운드 스캔이 끝난 뒤 동일 초 단위의 순위 보정이 적용되는지 확인.
- 제한보다 큰 저장 본문을 같은 작업 버전에서 반복하지 않고 실제 갱신 뒤에만 다시 판정하는 검사 추가. 저장 본문은 화면 표시 전용이며 소유자·입력 권한을 만들지 않고, 실제 GPU 스냅샷을 받으면 교체되는 기존 안전 조건을 유지.
- 포함 런타임 자동 검사 **255개 통과**, 건너뜀 0. 실제 0.19.5 초기 후보에서 창 표시 전 전체 스캔 때문에 약 48초가 걸리고 큰 본문 두 개가 반복 실패하던 진단을 재현한 뒤 수정.
- 최종 Windows x64 ZIP은 함께 게시하는 `.sha256` 파일로 검증. 배포 파일 104개 감사와 실제 Windows 사용자 경로의 설치·재설치·변조 거부·제거·데이터 보존·실행 중 버전 복구를 통과. 같은 ZIP을 노트북과 GPU에 설치했고 GPU의 기존 공식 Codex 프로세스 16개가 유지됨.

## 0.19.4 — 긴 대화 과거 턴 페이지

- GPU 공식 CLI 0.155.0-alpha.9.2에서 24턴 작업을 `thread/turns/list`의 `full` 보기로 두 페이지 읽어 서로 다른 이전 턴과 계속되는 `nextCursor`를 확인. 업무 메시지·승인·작업 실행은 0건.
- 연결 창이 보내는 페이지 요청을 작업 ID와 제한된 조회 인수에만 묶고, 목록에 없는 작업·추가 필드·빈/과대 커서·과대 페이지·중복 턴을 거부하는 자동 검사 추가.
- 최근 실시간 상태와 과거 저장 페이지를 구분하며, 과거 조회가 `watch`, `activate`, `submitText`를 발생시키지 않는지 검사.
- 완성된 배포 ZIP을 노트북과 GPU에 설치한 뒤, 설치된 GPU 처리기로 같은 24턴 작업의 서로 겹치지 않는 과거 페이지 두 개를 다시 읽어 실제 설치 경로를 확인. 기존 GPU Codex 프로세스와 노트북 연결 설정·아이콘 보존.

## 0.19.3 — Codex 업데이트 및 오래된 본문 구분

- 노트북과 GPU에 설치된 Codex 26.915.4065.0에서 소유자 조회 v1, 상태 스트림 v11, 팔로우 v1, 입력 v2, 모델 설정 v2, 지원 승인 v1, 중지 v4, 개입 v1 규약이 양쪽에서 일치함을 설치 파일 읽기 전용 검사로 확인.
- GPU 공식 CLI 0.155.0-alpha.9.2의 별도 읽기 전용 프로세스로 최근 작업 목록과 각 작업의 저장된 턴을 조회. 업무 입력이나 승인은 전송하지 않음.
- 연결 실패 안내가 원래 GPU 본문과 대기 요청을 변경하지 않고 화면 복사본에만 붙는지, 최신 스냅샷을 받으면 사라지는지 기존·정규화 대화 구조에서 자동 검사.
- 실제 연결 창의 최신 본문 갱신, 입력, 모델 선택, 보관 왕복은 양쪽 0.19.3 설치 후 별도로 검증.

## 0.19.1 — 대화 재연결

- 실제 GPU의 같은 대화를 사용하는 별도 진단 연결에서 SSH를 한 번 끊었다가 복구. 이전에 저장한 높은 상태 번호를 재현한 뒤 같은 소유자의 최신 전체 대화와 낮은 새 상태 번호를 받아 온라인으로 복구함을 확인. 업무 입력·승인 전송 없음.
- 연결 복구 시 현재 보고 있는 작업만 다시 열기, 읽기 전용 연결의 열기 금지, 다른 소유자·작업·이전 연결 응답·로드 중 응답 거부 및 온라인 상태 번호 역행 거부를 자동 검사.
- 실제 사용 중인 연결 창의 교체와 화면 갱신 검증은 배포 후 별도 확인 대상.


## 0.19.0 — 공통 팝업 응답

- 포함 런타임의 전체 자동 검사 **224개 통과**. 배포 파일 100개 감사 통과. 실제 Explorer 환경에서 ZIP 설치·재설치·변조 거부·제거·데이터 보존 및 실행 중 버전 보호/복구 통과.
- 노트북·GPU의 별도 버전 설치 후 기존 설정·아이콘·GPU 앱 프로세스 보존 확인. 새 GPU 작업자가 정확한 기존 세션 스냅샷과 대기열을 읽음. GitHub에 게시된 ZIP/체크섬 자산 digest 일치 확인.
- 이미 열린 이전 연결 창은 초안 손실을 방지하기 위해 재시작하지 않았다. 설치 갱신과 현재 창에서 새 코드가 실행되는 상태를 구분한다.

- 격리된 IPC에서 파일 변경·질문·일반 MCP 응답의 원래 소유자, 요청 ID/형식, 응답 값, 버전, 한 번 전송을 검사. 다른 소유자·변경 요청·오래된 상태는 거부.
- 파일 diff 변경, 질문 ID·부분/빈 답변, 네트워크 정책 대상/선택, STDIN 콜백, 폼 타입·필수 값·열거 선택·범위, 허용 기간 확대 거부를 검사. 기록에는 질문·폼 원문을 저장하지 않음.
- 계획 실행은 원본 계획/마지막 완료 턴을 대조하고 GPU 지침을 유지한 Default 모드의 새 턴으로 전송하는 격리 검사. 편집된 계획은 이 경로에서 거부.
- 직접 JSON-RPC 응답 뒤에도 WebSocket이 유지되고 다음 읽기가 성공하는 회귀 검사. 이 응답은 다른 프로세스의 요청으로 전달하지 않음.
- 미지원 안내가 GPU 요청/기록을 변경하지 않으며 요청 해제 후 사라지는지 검사. 형식이 달라진 요청은 연결을 끊지 않고 GPU 처리 필요로 분류.
- 실제 업무 승인·인증·플러그인 설치는 자동 실행하지 않았다. 추가한 모든 팝업의 실제 노트북/GPU UI 왕복은 별도 미완료이며, 지원표의 제한은 유지한다.

## 0.18.3 — MSIX 설치 환경 분리 및 권한·대기열 조회

- Windows 파일 핸들의 실제 경로로 앱 전용 LocalCache 리디렉션 확인. 동일 사용자 Explorer 프로세스에서는 기존 client.json이 없다는 사실을 별도로 재현.
- Explorer가 시작한 패키지 신원 없는 프로세스에서 0.18.2 설치·설정 복구 후, client.json과 node.exe의 실제 경로가 일반 AppData임을 검증. 같은 바탕 화면 아이콘으로 상태 스트림과 입력 가능 상태 확인.
- 설치 파일 복구 단위 시험은 별도 가상 패키지를 사용하며, 실행 환경 검사는 실제 Windows 파일 핸들과 정션을 사용. 패키지 신원이 없다고 보고되는 하위 프로세스에도 리디렉션이 남는 사례를 확인하여 신원 검사만 쓰는 방식은 제외.
- 이전0.18.2의 앱 내부 실행 성공만으로 바탕 화면 실행을 검증했다고 볼 수 없었음. 이 차이를 설치 안내와 검증 절차에 반영.
- 실제 호스트 CLI 0.153.4에서 대기열 읽기 성공. 양쪽 앱의 권한 승인 메서드 v1 및 GPU에 대기 중인 인터넷·폴더 접근 요청 형식 확인. 실제 승인을 대신 보내는 검사는 하지 않음.
- 합성 IPC 서버에서 권한 응답의 정확한 소유자·요청·허용 기간 전달, 확대된 권한 거부, 재시작 후 중복 방지 확인. 대기열 페이지 조회·캐시 제외·실패 전파·쓰기 거부 검사.


## 0.18.2 — Codex 업데이트 호환성

- 실제 클라이언트 26.908.4834.0, 호스트 26.903.8094.0 설치 파일의 규약 확인: 모델 설정만 v2/v1 차이, 소유자 조회·입력·지원 승인·상태 스트림 버전 유지. 호스트 CLI 0.153.4 확인.
- 포함 런타임 Node.js 24.20.0으로 자동 검사 183개 통과. 격리된 IPC 시험 서버에서 조건부 요청은 호스트에 보내지 않고, 일반 변경은 정확한 소유자에게 v1으로 한 번만 보내며 확인 응답을 v2로 변환하는지 검사.
- 기존 업무 지시나 승인 재전송은 검증에 사용하지 않음. 이 검사 결과는 Android 전체 UI나 지원표 밖의 앱 검증을 의미하지 않음.


## 0.18.1 — 코드 검토 후 수정

- 포함 런타임 Node.js 24.20.0으로 자동 검사 **180개 통과**, 건너뜀 0.
- 임시 설치 환경에서 설치·재설치·변조 거부·제거·사용자 데이터 보존 확인.
- OneDrive 클라우드 표식이 있는 압축 해제 폴더를 설치 소스로 사용해 성공. 실제 정션을 만든 자동 검사에서는 설치 복구를 거부함.
- `scripts/Test-LegacyRecovery.ps1`로 실제 `Get-CimInstance Win32_Process`를 호출. 임시 버전 폴더에서 노드 프로세스가 실행 중이면 복구 거부, 종료 후에는 원본을 보존하며 복구 성공. 일반 단위 픽스처의 가짜 프로세스 목록과 구분.
- 같은 SID 이름 충돌, 다른 SID 이름 동시 생성, 실제 Windows 토큰 SID 조회 확인. 서로 다른 사용자가 공식 앱까지 동시에 실행하는 전체 흐름은 미검증.
- 연속 진단 갱신 1,000회를 한 번의 기록으로 병합하는 검사, JSON 동시 읽기, 공유 잠금 실패 후 복구, 종료 시 제한된 재시도, PID 재사용 시 연결 파일명 충돌 방지 확인.
- 진단 폴더 삭제와 디스크 부족 시 예외 격리, 실제 Windows abandoned mutex 복구, 설치 명세 복사 손상 거부 및 클라우드/링크 태그 분류 검사 통과.
- 이 수정 검사는 GPU 업무 실행이나 Android Remote 전체 UI 회귀 검증을 대체하지 않음. 이전 0.18.0 ZIP은 보존하고 0.18.1을 별도 배포함.

## 0.18.0 공개 시험판

0.18.0 공개 시험판을 준비하며 다음을 확인했습니다.

- Windows 자동 검사 **167개 통과**: 연결 설정 분리, SSH 지문 일치/불일치, 잘못된 인수 거부, 호환성 차단, 캐시 탐색, 입력·승인 중복 방지, 본문 사전 읽기, 목록 정렬, 창 식별, 원격 실행 제한.
- 포함 런타임과 Windows 셸 사이에서 한글·이모지의 양방향 바이트 전달, 표준 입력 종료 후 프로세스 종료 확인.
- 임시 사용자 폴더에서 실제 설치, 같은 버전 재설치, 변조된 설치 파일의 재설치 거부, 제거 및 사용자 데이터 보존 확인.
- 두 Windows PC의 실제 SSH 연결에서 앱/CLI/IPC 진단 성공. 같은 26.901.6511.0 앱의 관련 프로그램 파일 해시와 연결·입력·승인 메서드 버전 일치 확인.
- 새 설정과 원격 설치 경로로 실제 작업 목록 10개 조회, 작업 ID 형식과 한글 제목 전달 확인. 해당 조회는 SSH 작업자 시작을 포함해 약 1.3초였으며 작업 클릭 화면의 지연 측정은 아닙니다.
- 배포 소스와 ZIP에서 개인 기록·계정·키·프로필을 제외하는 파일 명세 검사, 공식 Node.js ZIP 및 배포 파일 SHA256 검증.

기존 개인용 버전에서 확인했던 공식 화면의 작업 선택·입력·모델 변경·지원 승인 동작을 이어받았습니다. 첫 공개 패키지의 모든 UI 동작을 새로운 사용자 PC마다 재현했다는 뜻은 아닙니다. 다른 OS, 알 수 없는 Codex 빌드, 지원표에 없는 승인 종류는 검증 완료 범위에 포함하지 않습니다.
